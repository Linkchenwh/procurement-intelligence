# 模型与数据流

`data/raw`保留来源原文件 → 各域独立清洗 → `data/processed/*.parquet` → SQL/Python对账 → `outputs/tables`/Streamlit/Power BI输入。

采购绩效订单表：一行一个PO_ID。供应商指标表：Supplier×Item_Category一行，不用该聚合表反向连接订单明细计算金额，以免重复。

政府表：来源行观察粒度；缺少官方LineNumber。除9个分类字段外完全相同的候选组全部隔离，数值异常另隔离。主分析每保留来源行一行，订单组合可能包含多行。每供应商编码维表一行，原名变体数另报。分类分析主用Acquisition Type，不展开UNSPSC再求和。

市场表：每商品销售渠道观察一行；quote_id唯一。同品牌多报价不等于多个合同供应商。每情景×quote_id一行；不能跨情景求和为采购实际支出。

三域不建立共同供应商、共同日期或共同品类维表。它们只共享计算方法和界面结构。Power BI星型关系、筛选方向见 `dashboard/powerbi/README.md`。用户上传与正式数据不合并，当前会话选择上传即以该文件独立分析。

治理检查：每次关联先验证维键唯一，关联后核对行数与金额。当前BI名称通过单值映射展示；不把存在多名称的字典直接JOIN到事实。NULL保持未知，率先核对分子和有效分母。

Power BI 政府订单身份：`GovFact.order_key`保留来源精确组合，导出时按精确字符串生成整数`order_id`，DAX对整数做DISTINCTCOUNT。这样避免文本排序规则将仅大小写不同的24个身份合并；198,343个订单组合与SQL/Python一致。相同精确键的多行共用ID，金额和335,550行粒度不改变。整数ID属于快照，不保证不同数据版本间相同。
